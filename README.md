# Операционный CRM - frontend

## Запуск

```bash
cd "/home/user/BA_LandochkinaA/Операционный CRM/prototype-mvp"
npm install
npm run dev
```

Production-сборка:

```bash
npm run build
npm run preview
```

Если на репетиции менялись данные, перед финальным показом открыть служебный адрес сброса: к текущей ссылке Vite добавить `#/reset-data`.

Пример:

```text
http://localhost:5184/#/reset-data
```

После открытия адреса CRM восстановит исходные тестовые данные, вернет роль `Куратор CRM`, откроет `Главная` и уберет служебный хвост из адресной строки.

Сброс тестовых данных через интерфейс: в правой части верхней панели нажать кнопку с иконкой возврата.

Дополнительная команда для разработчика:

```bash
npm run reset-data
```

После команды обновить открытую страницу CRM. Если dev-сервер уже запущен, Vite обычно перезагружает страницу автоматически. При следующей загрузке состояние восстановится из исходного набора данных.

## Роли

- **Куратор CRM**: ведет юридических и физических лиц, запускает процессы, создает задачи, фиксирует коммуникации.
- **Исполнитель подразделения**: видит очередь задач своего подразделения, меняет статусы, делегирует задачи.
- **Руководитель процесса**: контролирует процессы, сроки, эскалации, отчеты и журналы.
- **Администратор BPM**: управляет конструктором процессов, справочниками, логированием и техническими обменами.

Переключатель роли находится в правом верхнем углу. При смене роли меняются меню, действия и сценарии.

## Экраны

- **Главная**: command-center, KPI, кликабельные диаграммы, очередь задач, процессы на контроле, риски и нотификации.
- **Клиенты и контрагенты**: единый реестр ФЛ и ЮЛ с поиском, фильтрами, сортировкой, скроллом по таблице, сохранением фильтров, созданием, редактированием и удалением.
- **Карточка клиента/контрагента**: вкладки общей информации, процессов, задач, документов, коммуникаций и истории; состав общей информации отличается для ФЛ и ЮЛ. В общей информации есть компактный блок контрольных сигналов с источниками расчета и кликабельные основные контакты с действиями звонка/письма. Во вкладке `Документы` видны назначение файла, сервис, договор/версия, связанный процесс, задача и следующий контрольный шаг.
- **Коммуникации**: рабочая очередь куратора по звонкам, встречам, письмам и follow-up действиям по всем закрепленным ФЛ/ЮЛ; из списка можно открыть карточку контрагента, зафиксировать итог и создать задачу. В карточке контрагента эта же информация показана как история общения по конкретному клиенту.
- **Поручения подразделениям**: доступны из карточки процесса и карточки задачи; можно передать работу внутреннему подразделению, задать срок, связать поручение с процессом и автоматически создать задачу.
- **Процессы**: kanban и таблица экземпляров BPM, запуск процесса, контроль обязательных задач этапа, остановка процесса.
- **Карточка процесса**: маршрут, текущий этап, связанные задачи, документы, ЭВД и история; технические обмены доступны администратору.
- **Задачи**: реестр задач, операционная карточка исполнителя, клиентский контекст, SLA, риски, материалы, выполнение результата, делегирование и откат.
- **Отчеты**: реестр отчетных форм по клиентам, процессам, задачам, интеграциям, документам и аудиту; поиск, фильтры, формирование отчета и выгрузка в файл.
- **Конструктор процессов**: версии шаблонов, визуальный маршрут, атрибуты форм, правила валидации, интеграционные правила.
- **Технические обмены и импорт**: админский раздел со статусами обменов, ошибками, повтором обмена, логом обмена и проверкой импортируемого файла.
- **Wiki**: централизованная база знаний с пространствами, иерархией страниц, полнотекстовым поиском по содержанию/версиям/вложениям, просмотром версий, загрузкой и скачиванием файлов.
- **Справочники**: структура справочников, поля, типы данных, обязательность, формулы и записи.
- **Журналы**: обезличенные действия пользователей, системные события, межсистемные взаимодействия и ошибки.

## Ключевые сценарии

1. Открыть `Главная` и переключить роль.
2. В `Контрагентах` найти `СРБ` или `КО-000184`, открыть карточку.
3. В карточке контрагента запустить процесс подключения к СБП.
4. Открыть карточку созданного процесса и нажать `Контроль этапа`.
5. В открытой задаче отметить обязательные результаты и нажать `Выполнить этап и передать дальше`.
6. Открыть раздел `Коммуникации`, отфильтровать запланированные контакты, перейти в карточку контрагента, зафиксировать итог звонка/встречи и создать follow-up задачу.
7. В карточке процесса открыть вкладку `Поручения`, создать поручение юридическому или технологическому подразделению и провести статус до следующего этапа.
8. Открыть процесс `BP-2026-0910` по договорным условиям Норд Капитал Банк: показать задачи, документы, поручение HND-9101 и статус обмена с СЭД.
9. Запустить для ФЛ процесс `Обработка обращения клиента` или `Актуализация профиля и согласий` и пройти этапы через карточку процесса.
10. В `Задачах` открыть задачу, отметить обязательные результаты, заполнить результат работы и выполнить задачу.
11. Если задача является текущим этапом процесса, нажать `Выполнить этап и передать дальше`: текущая задача закроется, процесс перейдет на следующий этап и создаст следующую задачу.
12. Под ролью `Администратор BPM` открыть `Тех. обмены`, посмотреть лог ошибочного обмена и повторить обмен.
13. В `Импорте` проверить файл `contacts_gts_2026-08.xlsx`: CRM покажет ошибки и создаст задачу на исправление.
14. В `Отчетах` выбрать отчетную форму, изменить период/формат/порог риска, нажать `Сформировать`, затем выгрузить файл.
15. В `Конструкторе` добавить этап, правило, опубликовать или откатить версию процесса.
16. В `Wiki` найти инструкцию по всей базе знаний, ограничить поиск пространством, открыть версию страницы, скачать вложение или открыть схему процесса.
17. Под ролью `Администратор BPM` создать пространство или страницу Wiki, отредактировать содержание, опубликовать версию, добавить файл и удалить страницу.

## Типовые бизнес-процессы

- **Подключение контрагента к сервису СБП**: профиль, технологическая проверка, промышленный запуск.
- **Запуск совместной маркетинговой акции**: расчет бюджета, операционный контроль запуска.
- **Выставление уведомления и штрафа контрагенту**: юридическое основание, контроль реакции.
- **Обработка обращения клиента**: регистрация обращения, операционная проверка, закрытие и контроль удовлетворенности.
- **Актуализация профиля и согласий ФЛ**: проверка данных, запрос подтверждения у клиента, публикация изменений в целевых системах.
- **Актуализация реквизитов и контактных лиц ЮЛ**: проверка реквизитов и контактов, запрос подтверждения у контрагента, публикация изменений в целевых системах.
- **Оформление договорных условий обслуживания**: проверка договорного пакета, согласование условий, контроль подписания в СЭД, активация параметров в CRM.

## Имитированные интеграции

- **СЭД**: проверка зарегистрированных обращений и связанного ЭВД.
- **BI/DWH**: передача метрик процессов и параметров отчетности.
- **Jira/Redmine**: создание связанных технологических задач.
- **Confluence/Wiki**: миграция знаний и контактов, ошибки валидации.
- **Телефония/Чат**: распознавание входящего обращения и открытие карточки контрагента.
- **Email Gateway**: отправка уведомлений и эскалаций, повтор обмена при ошибке.

## Автоматическое создание задач

В шаблонах процессов каждый этап связан с шаблоном задачи. При запуске процесса создается первая задача. При выполнении обязательной задачи этапа и нажатии `Выполнить этап и передать дальше`:

1. текущая задача этапа переводится в `Выполнена`;
2. процесс переходит на следующий этап;
3. создается следующая задача нужной группе исполнителей;
4. создается внутрисистемное уведомление;
5. событие записывается в историю процесса и обезличенный журнал.

Для новых типовых процессов настроены отдельные автозадачи: классификация обращения, операционная проверка обращения, контроль удовлетворенности, проверка состава профиля ФЛ, запрос подтверждения данных/согласий, проверка реквизитов ЮЛ, запрос подтверждения реквизитов и публикация изменений.

## Wiki

- **Блокирующие требования**: централизованная база знаний, полнотекстовый поиск по всей Wiki, навигация по пространствам и страницам.
- **Пространства**: CRM+BPM, Операционный контроль, Шаблоны коммуникаций, Технический контур.
- **Страницы**: иерархический список с дочерними регламентами, инструкциями по ФЛ/ЮЛ, шаблонами ответов и правилами повторного обмена.
- **Версии**: каждая страница хранит историю изменений; выбранную версию можно просмотреть, администратор может восстановить ее как новую запись истории.
- **Файлы**: вложения имеют тип, формат, размер, владельца и дату загрузки; скачивание имитируется через локальный файл, загрузка добавляет файл в карточку страницы.
- **Схемы и таблицы**: страницы с BPM-схемами и контрольными таблицами показывают рабочие превью; действия открытия схемы и скачивания таблицы кликабельны.

## Расчеты

- **Полнота профиля**: реквизиты 25 + контакты 20 + сервисы 25 + процессы 15 + документы 15.
- **Индекс риска**: базовый риск + просрочки * 9 + инциденты * 3 + штрафы * 12 + активные процессы * 2.
- **SLA задач**: выполнено вовремя / закрытые задачи * 100.
- **SLA процесса**: выполненные задачи процесса / все задачи процесса * 100.
- **Контроль срока процесса**: остаток дней до due date; риск подсвечивается при остатке меньше 2 дней или просрочках.
